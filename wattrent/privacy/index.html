Account & Data Deletion / 帳號與資料刪除

WattRent (developer: Yu-Chuan Chen / Raymond Chen) lets you delete your account and all associated data at any time. There are two ways:

  • In the app: open WattRent → Settings → Account → Delete account, then confirm. Your account and data are removed immediately.
  • By email: if you cannot open the app, email onepiece010938@gmail.com from your registered address with the subject "Delete my WattRent account". We verify the request and delete your data within 30 days.

Data that is deleted: account email, display name, meter readings, bills, uploaded meter photos, and app settings.
Data that is kept: nothing tied to your identity, except minimal security / server logs required by law, which are automatically purged within 90 days.

WattRent（電費快拍，開發者：Yu-Chuan Chen / Raymond Chen） 提供隨時刪除帳號與所有相關資料的方式，共有兩種：

  • App 內刪除：開啟 WattRent →「設定 → 帳號 → 刪除帳號」， 確認後即立即刪除您的帳號與資料。
  • 以 Email 申請：若無法開啟 App，請用您註冊的信箱寄信到 onepiece010938@gmail.com， 主旨填「刪除我的 WattRent 帳號」。我們確認後會在 30 天內刪除您的資料。

會刪除的資料：帳號 Email、顯示名稱、電表度數、帳單紀錄、 已上傳的電表照片、App 設定。
會保留的資料：除法律要求的最少量安全 / 伺服器日誌（90 天內自動清除）外， 不保留任何可識別您的資料。

2. What data we collect

2.1 Data you give us

  • Device & diagnostic data: OS version, app version, model, locale, crash stack traces (via Sentry). Used for bug fixing and performance monitoring. Does not include your email, photos, or bill content.
  • Advertising ID (IDFA / GAID): collected by the Google AdMob SDK to serve relevant ads and prevent ad fraud. You can reset or disable it any time in your device's system settings.
  • Server access logs: API request timestamps and HTTP status codes stored in Google Cloud Logging for debugging and security. Retained for 30 days.

9. Security

  • All API traffic is encrypted with HTTPS / TLS 1.3.
  • Passwords are stored using Firebase Authentication's industry-standard salted hashing (we never see your plain-text password).
  • Meter photos live in a private GCS bucket and can only be reached through short-lived (1 h) signed URLs issued by our backend to you.
  • Firestore security rules restrict each user to reading and writing only their own data.
  • Our backend service account uses GCP Workload Identity Federation — no long-lived keys.
